SIM300 Fleet Manager for Node-RED API

Reference for the APIs called by the Fleet Manager to authenticate, monitor, and manage SIM300 application configuration.

Design boundary The flow uses APIs for control-plane actions. High-frequency process data remains on Modbus TCP, and runtime write APIs are intentionally not exposed by the default Dashboard.

1. API bases and authentication

APIBaseUse
Application / CROWNhttp://<device-ip>:<app-port>Login and application configuration
SIM300 systemhttp://<device-ip>Firmware, identity, and health
POST http://<device-ip>:<app-port>/auth/login
Content-Type: application/json

{ "realm": "admin", "username": "admin", "password": "<password>" }

Tokens are cached per device in global.sim300.tokens. A 401 or 403 clears the cached token and triggers one re-authentication attempt.

2. System monitoring APIs

MethodPathFleet Manager use
GET/api/v1/system/infoDevice identity and firmware
GET/api/v1/system/monitor/statsCPU, memory, storage, and temperature

Memory is calculated as used / total * 100. Storage uses /datafs, falling back to the first partition. Temperature is the highest value in the response. A reachable device is Warning when a configured threshold is reached.

3. CROWN application APIs

CROWN requests use the application endpoint:

POST http://<device-ip>:<app-port>/api/crown/App/<api-name>
Content-Type: application/json
Authorization: Bearer <token>

{ "data": {} }

For APIs with a payload parameter, encode the payload as a JSON string when required by the application API. The flow normalizes text responses by removing a UTF-8 BOM, whitespace, and trailing NUL bytes.

The exact request and response schema is defined by the SIM300 application API. Keep register quantity compatible with its linked endpoint. Clone remaps source register IDs to newly created target IDs before recreating endpoints.

5. Requests, responses, and state

A CROWN response is a failure when header.status != 0 or data.success === false. When data.data is itself a JSON string, the flow parses it again.

Runtime state uses these Node-RED global keys:

sim300.settings
sim300.fleet
sim300.tokens
sim300.states
sim300.backups
sim300.jobs
sim300.configCache
sim300.monitorInFlight

Monitoring uses monitorIntervalMs, default 60000 and minimum 1000. An in-flight lock prevents duplicate monitoring requests for the same device.

6. Security and excluded APIs

Protect credentials in Node-RED global context and never commit production passwords or access tokens to an exported flow. The default UI intentionally does not call writeModbusRegisters or writeIOLinkEndpoint; these can actuate equipment and require a controlled commissioning workflow.

Also excluded are redundant single-item getters, IODD/process-data discovery APIs, advanced numeric or binary APIs, and internal initialization APIs.
